## 1. Why (goals & business context)

**Purpose:** Customers complete checkout on the public site; orders must **persist in Supabase** and appear on a **staff admin** area. Staff are not technical—they need a **menu** they can understand, not database jargon.

**Drivers:**

- **Checkout → DB:** Web orders must be created reliably via a single, auditable path (RPC), then WhatsApp opens with an order reference.
- **Admin visibility:** Orders and catalog must respect **RLS** while still allowing **only staff** to see operational data.
- **Trust:** Staff accounts must be explicitly linked (`public.admins`); anonymous visitors must not get silent “empty” admin screens without explanation.
- **Operations:** Static hosting (e.g. GitHub Pages) means the **public catalog HTML** is produced at **build time** unless we later add client-side catalog loading—staff need honest copy about **republish** after menu edits.

## 4. How (technical approach)

**Checkout RPC**

- **`SECURITY DEFINER`** + `SET search_path = public` so the function runs with **owner** privileges and **bypasses RLS** on owned tables for inserts/FKs/`RETURNING`, while **`GRANT EXECUTE`** remains for `anon` to **call** the RPC only.
- **Not** relying on long-term **`anon` INSERT** on `orders` / `order_items` for checkout (migration 006 drops those policies after the experiment in 005).

**Staff checks**

- `getStaffSupabase()`: `auth.getSession()` + **`select` from `admins`** filtered by **`user_id`** + `maybeSingle()` → if no row, show explicit message pointing to **`docs/seed-admins.md`** (filter avoids multi-row RLS confusing `maybeSingle()`).

**Menu admin**

- Loads products, categories, options, `product_i18n`, `product_option_i18n`
- Add/edit saves via **`MenuItemModal`** (insert/upsert/update/delete options with care around FKs, e.g. recipe lines blocking option delete)
- Responsive: **`xl:hidden`** card list / **`hidden xl:block`** table

**Static site & catalog**

- `loadCatalogProducts()` (server/build) reads Supabase when build env is set; else falls back to `src/data/products.ts`. **Changing menu in admin updates DB immediately**; with **`NEXT_PUBLIC_SUPABASE_*`** set, the **browser also refetches** the catalog on menu/product pages so the live list updates without redeploy (static **routes** for brand-new product IDs may still need a rebuild on pure static hosts).

## 5. What went wrong (symptoms → root cause)

| Symptom | Root cause |
|--------|------------|
| **403** on `POST .../rpc/create_order_from_checkout` | **`SECURITY INVOKER`** path: `anon` could not satisfy **FK checks** and **`INSERT … RETURNING`** under RLS. |
| **Migration 005** alone not enough | Same invoker/RLS constraints; later **006** restores **`SECURITY DEFINER`** and revokes temporary anon INSERT policies. |
| **Orders list empty** with no error | **`is_admin()` false**: signed-in user **not** in **`public.admins`** → RLS returns **zero rows**. |
| **GET /admin/orders 500**, missing `routes-manifest.json`, `Cannot find module './331.js'` | **Corrupt / incomplete `.next`** (often deleting `.next` while `next dev` still running, or Windows cache/AV). |
| **Favicon 500** | Same broken build + missing chunk for generated favicon route; mitigated with **`public/favicon.ico`**. |
| **“Not all products/options” in early admin UI** | DB seed matches **four** products in `src/data/products.ts`; **options** existed in DB but **UI** didn’t show them clearly until later iterations. |
| **Menu UI “messy” for owner** | Too much technical surface (slugs, jargon); addressed with **search + table/cards + modal** and plain labels. |
| **Delete too easy** | Single confirm; addressed with **two-step** confirm + clearer **Delete** labeling. |
| **“Not linked as staff” with row in `admins`** | Unfiltered `admins` **SELECT** under RLS returned **multiple rows**; **`maybeSingle()`** failed → fixed by **`.eq("user_id", session.user.id)`** in `getStaffSupabase()`. |

## 6. What we did to fix (chronological narrative)

1. **Checkout RPC:** Moved to **`SECURITY DEFINER`** (migration **006**), removed reliance on **`anon` INSERT** policies from **005** for the long-term model. Applied to **remote** DB via **`supabase db push`**.
2. **Admin orders/dashboard:** Introduced **`getStaffSupabase()`** before loading orders; surfaced **staff not linked** message; optional **auth subscription** to refetch (orders page).
3. **`.next` / 500:** Advised **stop dev server → delete `.next` → restart**; added **webpack `cache: false`** in dev, **`public/favicon.ico`**, **README** troubleshooting. (Later: default dev switched back to **Webpack** after Turbopack `_buildManifest.js.tmp` ENOENT on Windows.)
4. **Menu admin v1 → v2:** Card-style “menu items” editor → replaced with **toolbar (search + Add)**, **table**, **modal** (`MenuItemModal`), **nav “Menu”**.
5. **Responsive:** **Cards** below **`xl`**, **table** from **`xl`** up.
6. **Actions:** **Outlined Edit (orange)** and **Delete (red)**; **two** `window.confirm` steps before delete.
7. **Documentation:** **`docs/seed-admins.md`** already describes Auth + `admins` inserts; **worklog** (this file) and **commit `c5cebc7`** document the larger drop.
